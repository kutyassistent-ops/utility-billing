# Учёт коммунальных платежей (ЖКУ)

Веб-приложение для учёта показаний счётчиков и коммунальных платежей.
Арендодатель заводит объекты и тарифы, арендатор вносит показания, счёт
считается автоматически.

Flask · Flask-Login · SQLite · Bootstrap 5

---

## Возможности

| | |
|---|---|
| **Роли** | `owner` — арендодатель, `tenant` — арендатор |
| **Объекты** | Адрес + индивидуальные тарифы по каждому объекту |
| **Показания** | Горячая вода, холодная вода, электричество; дата; защита от дублей и от убывания |
| **Счета** | Считаются автоматически при вводе показаний, с разбивкой по статьям |
| **Долг** | Сумма всех неоплаченных счетов по объекту |
| **Оплата** | Счёт закрывает только владелец объекта |
| **История** | Все показания, счета и кто их внёс |
| **Статистика** | Помесячные суммы и расход по каждому ресурсу, период настраивается |

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
python app.py
```

Приложение откроется на <http://127.0.0.1:5000>. База данных создаётся
автоматически при первом запуске — отдельная команда не нужна.

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `SECRET_KEY` | `your-secret-key-change-in-production` | Ключ подписи сессий Flask |
| `DB_PATH` | `huita_bd.db` | Путь к файлу базы |

```bash
# PowerShell
$env:SECRET_KEY = "сгенерируйте-случайную-строку"
$env:DB_PATH    = "data/huita_bd.db"
python app.py
```

> [!warning] Значение `SECRET_KEY` по умолчанию — только для локального запуска
> С ним сессии подписываются предсказуемым ключом. Перед публикацией
> обязательно задайте свой `SECRET_KEY` через переменную окружения.

## Как считается сумма

Берётся предыдущее показание по объекту, разница умножается на тариф.
Первое показание считается от нуля.

```
потребление_эл  = (Эл  − Эл_prev)  × tariff_el
потребление_хвс = (ХВС − ХВС_prev) × tariff_water
потребление_гвс = (ГВС − ГВС_prev) × tariff_water
отопление_1     = (ХВС − ХВС_prev) × tariff_com1
отопление_2     = ((ХВС − ХВС_prev) + (ГВС − ГВС_prev)) × tariff_com2

итого = потребление_эл + потребление_хвс + потребление_гвс
      + отопление_1 + отопление_2
      + fixed_fee
```

Значения тарифов по умолчанию (рублей) задаются при создании объекта и
редактируются отдельно для каждого объекта:

| Поле | По умолчанию | Что это |
|---|---|---|
| `tariff_el` | 2.73 | Электроэнергия, за кВт·ч |
| `tariff_water` | 31.21 | Холодная и горячая вода, за м³ |
| `tariff_com1` | 72.83 | Отопление, за м³ |
| `tariff_com2` | 21.95 | Отопление, за м³ (вторая составляющая) |
| `fixed_fee` | 17000 | Фиксированная плата за месяц |

## Маршруты

| Метод | Путь | Доступ | Что делает |
|---|---|---|---|
| `GET` | `/` | все | Редирект на дашборд или на вход |
| `GET`/`POST` | `/auth/login` | все | Вход |
| `GET`/`POST` | `/auth/register` | все | Регистрация с выбором роли |
| `GET` | `/auth/logout` | все | Выход |
| `GET` | `/dashboard` | вход | Сводка: объекты, последние показания, долг |
| `GET`/`POST` | `/add_property` | owner | Добавить объект |
| `GET`/`POST` | `/edit_property/<id>` | owner | Изменить адрес и тарифы |
| `GET`/`POST` | `/add_reading` | вход | Внести показания (свой объект) |
| `GET` | `/history/<property_id>` | вход | История показаний и счетов |
| `POST` | `/pay/<invoice_id>` | owner | Отметить счёт оплаченным |
| `GET` | `/stats` | вход | Статистика по месяцам |

Доступ к чужому объекту закрыт на уровне выборки: арендатор видит только
объекты из `tenant_properties`, арендодатель — только свои.

## База данных

SQLite, файл `huita_bd.db` **не хранится в git** — в репозитории лежит
только схема (`docs/schema.sql`).

| Таблица | Что хранит |
|---|---|
| `users` | Логины, хеши паролей, роль, ФИО, почта |
| `properties` | Объекты: адрес, тарифы, владелец |
| `tenant_properties` | Связь арендатор → объект |
| `meter_readings` | Показания по датам, уникальность `(property_id, date)` |
| `invoices` | Счета: сумма, разбивка по статьям, отметка оплаты |

Схема создаётся при старте (`init_db()`), миграции выполняются на месте:
если в таблице `invoices` нет колонки `paid` — она добавляется.

## Безопасность

- Пароли хешируются **bcrypt**, в открытом виде не хранятся и не логируются.
- `SECRET_KEY` берётся из переменной окружения.
- База данных с персональными данными исключена из git.
- Доступ к объектам проверяется на уровне SQL-запросов, а не только в шаблоне.

> [!warning] `app.py` запускается с `debug=True` и `host='0.0.0.0'`
> Это удобно для разработки, но небезопасно для общей сети: отладочный
> сервер и доступ извне. Перед выкладкой на общий ресурс уберите `debug=True`
> и поставьте за nginx/gunicorn.
